# 滑块/拼图验证码自动通过方案（AJ-Captcha 实战）

适用：anji-plus AJ-Captcha、及其带"干扰轮廓"的变体（背景图上有多个白色拼图轮廓，只有一个是真缺口）。

## 为什么不能盲拖 / 截图目测

- 截图有缩放（背景图原始 310×155，页面显示 360×155），目测误差轻松超过容差（±5 原始像素）。
- 多干扰轮廓时，"看起来最像"的轮廓大概率是假的——本项目首个真缺口残差 17.1，干扰项 25.0/36.1，视觉无法区分。

## 算法流程（成功率 ~100%）

1. **提取原图**：从 DOM 拿两张 base64 图，别用截图：
   - 背景 `img.backImg`（如 310×155）
   - 拼图条 `img.bock-backImg`（如 47×155，透明背景，拼图块在其中）
2. **拼图掩码**：按 alpha>128 取拼图 bbox（本项目 46×46），内部再腐蚀 2~4px 去掉白色描边。
3. **候选定位**：在背景图中找白色（RGB>215）连通域，bbox 尺寸 ≈ 拼图尺寸的即候选。
4. **暗化拟合判真**：真缺口的像素 ≈ 拼图内容 × 常数 k（k 用最小二乘求）。
   对每个候选算 `mean|bg_region − k·piece|`，残差最小者为真缺口。
   干扰轮廓只是画上去的线，内容与拼图无关，残差明显更大。
5. **坐标换算**：
   - 缩放比 = 显示宽 / 原始宽（360/310）
   - 目标拼图条 left = bg.left + gap.x × scale
   - **手柄"中心跟随鼠标"**：元素 left = mouse.x − halfWidth（本项目 20px），别漏！
6. **拟人轨迹拖拽**：mouse down 后分 6~8 段移动（带 ±1~2px 纵向抖动），末段先过头再回正，然后 up。
7. **实测映射**：拖动中途（不松手）读一次拼图条位置，确认位移与手柄位移比例（本项目 1:1），
   再按比例修目标点。

## 失败处理

- 失败会自动换图：重新提取、重新计算即可（脚本化整个流程，单次重试成本 < 10 秒）。
- 验证码图有有效期（几分钟），分析完尽快拖。
- 有的站点把验证码做成 iframe / 弹窗，注意切换 frame。

## 依赖

Python：Pillow、numpy。核心思路：连通域候选 + 暗化拟合残差排序 + 1:1 实测映射拖拽。
