# 选对形式再解释

## 为什么需要它

默认的解释方式是写长文字。文字适合精确表达，但讲结构关系很吃力，讲"改一下会怎样"读不出来，讲随时间展开的过程更差。LLM 现在能很便宜地生成图表、网页和视频，所以文字不够用时换形式几乎没有门槛。用户的工作越来越多是监督和理解，而不是亲手做，输出能不能让人快速看懂，比输出本身多漂亮重要得多。

目标是让用户理解，不是默认写长文，也不是炫耀媒体能力。

## 边界与优先级

- 用户明确指定了形式，就用指定的形式，必要时补一小段文字。用户只要简短回答、纯文字或低带宽输出时，不擅自升级。
- 不要问用户"你想要哪种形式"。除非缺失的信息会影响正确性，否则自己选合理的默认值。
- 形式由你根据本技能自己判断，不调用外部分类或推荐服务。核实事实和生成产物可以使用宿主允许的工具。
- 遵守宿主的权限和安全规则，本技能不增加任何工具权限。

## 四种形式

| 形式 | 适合 | 不适合 |
|---|---|---|
| 文字（STE 风格） | 结论、定义、精确约束、步骤、警告、简短问答 | 用长段落描述复杂关系或连续变化 |
| 图表/图像 | 结构、关系、流程、对比、数据、空间布局 | 信息很少，画图比文字更费劲 |
| 交互 HTML | 调参数、多方案比较、分层查看、主动探索 | 只有排版需求，没有交互收益 |
| 解释视频 | 抽象机制、连续变化、空间变换、需要被引导着看的复杂主题 | 静态图足够，或用户主要想查精确信息 |

阶梯表示表达能力和制作成本，不是质量排名。越靠后越直观，也越耗时。

## 路由：先找理解障碍，再选形式

在心里判断，不输出推理过程，也不让用户填问卷。先问：用户理解的主要障碍是什么？

| 主要障碍 | 默认选择 |
|---|---|
| 没有障碍，一个短答案或几步操作就够 | 文字 |
| 关系、结构、对比、数据、空间布局 | 文字 + 图表 |
| 需要自己改条件、看结果才懂 | 文字 + 交互 HTML（图表嵌入网页） |
| 抽象，且关键在一段随时间展开的变化，按顺序看明显优于静态读 | 文字 + 视频 |
| 既要自己探索，又要有人引导看一段关键变化 | 以 HTML 或视频为主，另一个补充 |

容易判错的三处：

- **有时间轴不等于要视频。** 历史事件用时间线。只有连续旋转、相位变化、算法状态演化这类"变化本身就是解释"的内容才需要动态演示。
- **内容复杂不等于要视频。** 复杂分类通常适合结构图，参数敏感性通常适合交互网页。
- **HTML 和视频都合适时，看谁掌握控制权。** 用户需要自己改条件，选 HTML。用户需要被引导观察一段变化，选视频。

拿不准时选低一档。用户觉得不够，再升级。

## 升级前检查

每次往高一档升级之前，确认以下五点都成立，否则停在当前层级：

1. 新形式解决了一个具体的理解障碍。
2. 更简单的形式无法同样清楚地完成。
3. 生成耗时、观看时间和操作负担与收益相称。
4. 当前能力真的能生成可用的产物，而不只是描述它。
5. 没有违反用户的格式、时长、设备或可访问性约束。

通过检查的定制产物，大胆去做。一次性使用不是偷工减料的理由。视频耗时最长，信号不够强时（用户只是随口问问），先给文字和图，再用一句话提议"需要的话可以做成视频"。

## 组合：每种形式承担不同职责

默认是"一个主形式 + 简短文字"。只有新增形式带来独立收益时才继续加。不要把同一篇长文分别塞进图、网页和视频。

| 组合 | 分工 |
|---|---|
| 文字 + 图表 | 文字给结论与限制，图表展示关系或证据 |
| 文字 + HTML | 文字给核心规律，网页让用户操作并检验 |
| 文字 + 视频 | 文字给可检索的结论，视频展示关键变化 |
| HTML + 视频 | 视频先建立直觉，网页让用户改条件验证直觉 |

文字几乎总是保留：哪怕主产物是图或视频，也配一小段文字结论，保留公式、参数、步骤和适用边界。它最快，也最好检索。

## 生成

各形式的细则按需读取：

- 文字：`references/ste.md`
- 图表和网页：`references/diagrams-and-pages.md`
- 视频：`references/video.md`

## 交付与诚实

- 先说结论，再给产物。非文字主产物，用一句话说明为什么，例如"关键是参数之间的关系，所以我做成了可调节的页面"。简单问题直接答，不讲路由过程。
- 只报告已经完成并有依据的东西。没有实际测试，就不说"已测试通过"。没有真的生成视频，就不说"视频已生成"。无声视频不能说成已配音，脚本不能说成视频。
- 能力不够时降级：保留关键解释，换成能验证的形式（短片段、带字幕的版本、可运行的动画），并说明实际交付了什么。
- 没有真实数据时不编数据。教学用的模拟数据要明确标注。
- 不在对话里索要明文密钥。
- 当前组合足以讲清楚时就结束，不追加长篇原理，也不每次问"还要不要网页或视频"。

## 路由示例

| 用户请求 | 选择 | 原因 |
|---|---|---|
| "什么是幂等？" | 文字 | 短定义加一个重复操作的例子 |
| "OAuth 里几个角色是什么关系？" | 文字 + 时序图 | 难点是角色之间的消息传递 |
| "比较三个套餐" | 文字 + 比较表 | 用户要准确查差异，不需要动画 |
| "复利受利率和年限怎么影响？" | 文字 + HTML | 自己调参数比看固定例子有价值 |
| "为什么傅里叶变换能分解信号？" | 文字 + 视频 | 动态叠加和旋转向量连接公式与直觉 |
| "列出某技术的发展历史" | 文字 + 时间线 | 有时间顺序，但不构成做视频的理由 |

## 常见错误

- 一律默认长文字，这是本技能要纠正的最大问题。
- 一律默认最炫的形式，简单问题做视频是在浪费用户时间。
- 形式没有承载信息：网页没有交互，视频只是在念文字，图表只是把文字框起来。
- 组合形式之间重复，每个形式要讲不同的部分。
