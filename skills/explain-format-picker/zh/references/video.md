# 解释视频（v2：两级方案）

风格目标：3Blue1Brown——先建立直觉，再引入符号；一个画面一个想法；画面的连续变化本身就是论证。不冒充原作者，不复制品牌标识，不模仿本人声音。

## 第 0 级——视频即页面（默认）

视频就是"按时间表变化的图表"。在编码任何 MP4 之前，先做**分步播放器页面**——这一模式由开源项目 [answer-me-with-html](https://github.com/QingYunA/answer-me-with-html) 推广：

- 一个自包含 HTML 文件：图表（SVG/Canvas/CSS）+ 播放条（播放/暂停、上一步/下一步、进度、倍速）。
- 草稿的旁白行变成**拍（beat）**；每一拍在图里揭示或移动一样东西（节点亮起、箭头画出、状态翻转）。"镜头"跟随当前拍的节点。
- 拍自动开始、按计时推进；字幕显示当前行；点章节直接跳转。
- 不需要 ffmpeg、不需要编码、离线可跑、文字可选中，而且每一拍的精确度等于它来源的草稿——不多不少。
- 配音：用户要声音且宿主有 TTS 才配；否则默认带字幕交付。字幕来自草稿行，渲染时不重写。

大多数"用视频讲"的请求，这一级就能满足。回复页面路径加一句话即可。

## 第 1 级——完整渲染（仅明确要求时）

用户**明确要视频文件**时才产 MP4/WebM：

- 动手前先查环境：Manim 画图；ffmpeg（或等价工具）合成；TTS 需实际可用且获授权。缺工具→说缺什么，退到第 0 级加分镜，并把分镜叫做分镜——绝不说成视频。
- 拍从同一份草稿渲染；抽查 1–2 帧看溢出、重叠、对比度。
- 交付文件 + 文字摘要（核心结论、关键参数、适用边界）。

## 草稿规则（两级通用）

- 结构：核心问题 → 建立直觉 → 动态机制 → 关键结论 → 适用边界。
- 一拍 = 一两句旁白；每拍只变一样东西；画面服务旁白（"两个量一起增长"⇒ 画面里两个量一起增长）。
- 时长按拍数算，不按野心算：短主题 8–15 拍；画幅 16:9（仅手机优先时 9:16）。
- 同一对象全程同名、同色、同符号；文字要少；每个变化都在说明一个关系；关键变换出现后留时间消化。
- 数学与数据必须精确——可控渲染，绝不用生成式画面。模拟数据标注 `示意`。

## 什么时候不要做视频

- 一张图加几句话就能讲清楚。
- 用户随口一问，没有表现出愿意花几分钟看。
- 内容是精确参考资料（命令、参数表）——视频反而难检索。

这些情况先给文字和图，再用一句话提议可以做成视频。
