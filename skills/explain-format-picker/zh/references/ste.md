# STE 风格写作要点（v2）

ASD-STE100（Simplified Technical English）是最初为航空维修文档设计的受控英语规范：写作规则（约 9 节）加词典（约 900 个核准词，每词一种词性、一个意思）。中文规则另参考了 Simplified Technical Chinese 词表。严格的限制逼出清晰的写法，读者很难读错。

v2 变化：以下规则由 `scripts/lint_draft.py` **机器检查**——对草稿跑脚本，不要靠肉眼校对。本文件解释检查器查什么、为什么查。

## 默认严格度

默认"约 80% 严格度"：保留短句、一词一义、主动语态，但允许句式有些变化，让文字不那么像说明书。

- 安全相关、步骤类、需要零歧义的内容：接近 100%。
- 一般性解释：约 80%。
- 用户可以直接指定（"用 80% 的 STE 程度解释"）。
- "80%"表示宽松程度，不是可测量的合规分数。只有能核对适用版本、词典和完整规则时才可说"符合 ASD-STE100"，否则一律称"STE 风格"。

## 精确限制（检查器执行的部分）

| 规则 | 上限 | 适用 |
|---|---|---|
| 句长（中文） | 35 字（步骤类）· 45 字（描述类） | 汉字 ≥4 的句子 |
| 句长（英文） | 20 词（步骤）· 25 词（描述） | 其余句子 |
| 段落长度 | ≤ 6 句 | 所有语言 |
| `的` 链 | ≤ 3 连 | 中文 |
| 被动语态 | 避免，写明谁执行 | 英文 |
| 轻动词 | 进行X / 加以X / 予以X / 做出X → 直接用 X | 中文 |
| 陈词滥调 | 赋能、抓手、闭环、打通、全方位、多维度、深度融合、显著提升、至关重要、不可或缺、综上所述、总而言之、众所周知、毋庸置疑、一站式、底层逻辑、颗粒度、方法论、值得注意的是、与此同时 → 换成具体事实 | 中文 |
| 错别字 | 登陆→登录、帐号→账号、阀值→阈值、布署→部署 | 中文 |
| 无数量词 | 尽快、若干、大概、大约、多次 → 写出数字（描述类可用"约"） | 中文 |
| 模糊边界 | 数字+以上/以下 → 写出端点；数字+以内 → 不超过 | 中文 |
| 一义多词 | 单击/点按→点击、键入→输入、入参→参数、出参→返回值、缺省→默认 | 中文 |
| 垫话词 | utilize→use、in order to→to、prior to→before、in the event that→if、it is recommended that→（写明谁建议） | 英文 |

有意展示的反例自动豁免：`~~删除线~~` 包裹，或放进状态为 `no` 的表格行。代码、数学、标题自动跳过。

## 检查器查不了、自己要守的规则

- 结论先行：先 1–3 句说核心结论，再展开。
- 一句一个主要意思；一步只含一条指令。
- 术语一致：同一概念全文同一个词；首次出现时解释。
- 指代明确：不用指向不明的"它/这个/上述内容"。
- 事实、假设、推断、示例、限制分开写，别揉进一句话。
- 简化不丢精度：否定条件、风险、单位、适用范围一个都不删。
- 警告在前：先说"不要做什么"，再说原因。
- 复杂内容竖排（列表），绝不塞进一个长句。

## 示例

原文：
> 在启动操作之前，操作员应确保液压油箱已经被充满。

STE 风格：
> 先确认液压油箱是满的。然后开始操作。

原文（检查器报告：赋能=滥调、进行优化=轻动词、至关重要=滥调）：
> 新引擎赋能数据处理管道，对查询模块进行优化，这一步至关重要。

STE 风格：
> 新引擎加速数据处理。查询模块做了三处优化：索引、缓存、批量写入。步骤 3 依赖这一步。
