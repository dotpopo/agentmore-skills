# 草稿中的多语言（v2）

一份草稿一次语言决策；下游一切读这个结果，不再各自判断。

## 决策顺序

1. **声明优先**——草稿 frontmatter 有 `lang:`（如 `lang: zh-Hant`、`lang: fa`）。声明的标签照原样保留；`zh` 一律写成 `zh-CN`。
2. **修补保持**——更新已有产物时沿用其语言，除非新草稿声明了别的。
3. **脚本检测**——按文字的书写系统判定：

| 文字 | 语言 |
|---|---|
| 出现假名 | `ja` |
| 汉字含简体独有字形 | `zh-CN` |
| 汉字含繁体独有字形 | `zh-Hant` |
| 汉字只有简繁共有字形 | 保持 `zh-CN`（繁体需声明） |
| 谚文 | `ko` |
| 西里尔字母 | `ru`（乌克兰语声明 `uk`） |
| 阿拉伯字母 | `ar`（波斯语声明 `fa`） |
| 希伯来字母 | `he` |
| 泰文 | `th` |
| 希腊字母 | `el` |
| 拉丁字母 | `en`（其他拉丁语言需声明） |

简繁判定数"只存在于一种形态"的字；短或用字平实的中文可能一个特征字都没有——按简体处理，除非声明。**书写系统定不了语言时必须声明**：阿拉伯字母也写波斯语，西里尔也写乌克兰语，拉丁字母还写法/德/越语。

## 语言决定什么

- **句长计数**：汉字 ≥4 的句子按字数，其余按词数。混排文本按句判定，不按整份草稿。
- **检查规则族**：`zh`、`en` 用全量检查（长度、被动/轻动词、词表、陈词滥调、错别字）；`ja` 只查长度（日语的「的」是后缀，不是结构助词，中文规则不适用）；**其他语言只做语言中立检查**（句长、段长）。没有词表就不要假装有。
- **文字方向**：阿拉伯语、希伯来语是 RTL——页面设 `dir`，镜像对齐，并确认图表阅读方向仍正确。
- **HTML 元数据**：`<html lang>` 用判定的标签；页面 UI 标签跟随。没有对应标签集的语言回退英文标签——用户需要知道时在页脚说明一句。
- **旁白与视频**：与草稿同语言。绝不为了交付自动把草稿翻成另一种语言；用户开口要求才翻译。

## 值得执行的排版细节

- 中英/中文与数字之间加细空隙（"使用 3 台服务器"）；中文日文正文用全角标点，代码和单位内用半角。
- 一份草稿一种语言一套术语：数字/number、配置/config 选定后全篇不改。
- 用户混用语言时：引用术语保留原文，首次出现处给一次翻译。
