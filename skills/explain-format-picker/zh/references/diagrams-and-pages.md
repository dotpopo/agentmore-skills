# 图表与交互网页

## 图表

选能直接表达问题结构的形式，不为装饰而画图。

| 内容 | 优先形式 |
|---|---|
| 分类与层级 | 树形图、结构图 |
| 操作、分支、状态转移 | 流程图、状态图 |
| 系统交互与消息顺序 | 架构图、时序图 |
| 属性与方案比较 | 比较表、比较矩阵 |
| 数量差异 | 条形图 |
| 连续数值趋势 | 折线图 |
| 相关性与分布 | 散点图、分布图 |
| 空间布局与部件关系 | 标注示意图 |
| 关键阶段变化 | 分步图、前后对照图 |

- 流程、关系、架构用 Mermaid 等声明式图形。定量图表用 HTML/CSS/JS 配合绘图库，遵循宿主的输出规则。
- 一张图只讲一件事。标签要清楚可读。数据图标明单位、类别和必要的数据范围。
- 需要精确公式或大量文字时，用可控排版的图表，不要把所有文字交给图像生成器。
- 每张图配一句"请注意什么"，不让用户自己找重点。
- 没有真实数据就不画"趋势"。教学用的模拟数据要标注。

## 交互网页

只有交互真的帮助理解时才做网页。

| 项目 | 要求 |
|---|---|
| 交付 | 可直接打开的单页 HTML，或宿主支持的可运行产物 |
| 依赖 | 优先内联 CSS、JS、SVG。离线产物不要暗中依赖 CDN、远程字体或在线接口 |
| 核心交互 | 围绕主要难点设滑块、开关、拖动、步骤切换或参数输入 |
| 反馈 | 操作后立刻看到结果，并能看出结果为什么变 |
| 初始状态 | 默认参数就能展示关键规律，不是空白状态 |
| 可恢复 | 提供重置。有时间动画就提供暂停和步进 |
| 可访问性 | 键盘可操作，标签明确，对比度足够，尊重"减少动态效果"偏好 |
| 正确性 | 区分真实计算、简化模型和视觉示意，标明重要假设 |
| 自足 | 页面里留一句简短结论和操作提示，不依赖外部文字也能读懂 |

没有交互收益的"漂亮排版"不算网页解释。如果环境支持渲染或测试，检查关键操作、边界输入和移动端布局；没测过就不说测过。
